How it works

Terraform + Ansible + your cloud. No magic, no lock-in.

cloudseed is a thin, deterministic driver. It writes plain Terraform, shows you the plan, and hardens hosts with Ansible — in your own account, with state you own.

  1. 1

    You ask

    From the CLI, the web console, an MCP client or cs agentic "…" — they all run the same command.

  2. 2

    cloudseed plans

    Renders a Terraform root per environment, picks a free CIDR, tags every resource and waits for your approval.

  3. 3

    Terraform builds

    Network, bastion, baseline and cluster — state local or in a versioned, encrypted bucket with locking.

  4. 4

    Ansible hardens

    sshd, fail2ban, auditd, nftables and security updates on the bastion and VPN hosts; RKE2 or kubeadm on VMware.

  5. {% include ".icons/material/check-decagram.svg" %}

    Your cloud

    AWS, Google Cloud, Azure or VMware on your laptop — the same shape everywhere.

Security and trust

Secure by default. Honest about it.

  • {% include ".icons/material/shield-lock-outline.svg" %}
    A bastion only you can reach. SSH is allowed from your IP alone (never 0.0.0.0/0); workloads live in private subnets; cs update-ip follows you when your address changes.
  • {% include ".icons/material/lock-check-outline.svg" %}
    Encryption and audit logging on. Encrypted disks and remote state, flow logs, CloudTrail and GuardDuty on AWS, audit logs on GCP, Log Analytics (and optional Defender) on Azure.
  • {% include ".icons/material/eye-off-outline.svg" %}
    Credentials never leave your machine. Agents run with secrets stripped from their environment and every line of output redacted; the vault, state and keys stay under ~/.cloudseed.
  • {% include ".icons/material/server-security.svg" %}
    Local by design. The console and the MCP server listen on loopback only, require a token and check Origin; changes over MCP need confirm=true. No telemetry anywhere.
  • {% include ".icons/material/history.svg" %}
    Reversible and auditable. cs undo for the last actions, an audit trail, redacted logs and an inventory with history for every environment.
  • {% include ".icons/material/package-variant-closed.svg" %}
    A small supply chain. A standard-library-only Python CLI, SHA256-verified tool downloads and chart versions pinned per release.

How it is verified

  • LiveVMware scenarios run for real on VMware Fusion; the agent and console scenarios on a local machine.
  • Dry-runAWS, GCP and Azure scenarios are rendered and validated with --dry-run; run them for real with your cloud credentials.
  • CIUnit tests, terraform validate and mocked terraform test suites on every change — no cloud access needed.
